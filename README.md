## Install

*   **Commande line installation:**
    ```bash
    python -m venv .venv && . .venv/bin/activate      # Windows : .venv\Scripts\activate
    pip install -r requirements.txt
    cp .env.example .env                              # LAB_PROVIDER / LAB_BASE_URL / LAB_MODEL
    ```

### Running Commands

The following commands are used to interact with the system, verify outputs, and run core tests. They are grouped by functionality for ease of use.

#### System Setup & Interaction (`lab`)

These commands handle general interaction, testing the live LLM connection, and managing conversational state.

*   **Validate Setup:**
    ```bash
    python -m lab ping
    # Purpose: Confirms that the local environment and API connections are working correctly.
    ```

*   **Streaming Chat (Standard):**
    ```bash
    python -m lab chat "Write a .env parser in Python" --mode gate
    # Purpose: Executes a real-time, stream-based chat session with the LLMService.
    ```

*   **Detailed Debugging Chat:**
    ```bash
    python -m lab chat "..." --mode gate --trace
    # Purpose: Runs a full streaming chat while capturing detailed logs for *every* LLM call (Generator prompt, Judge prompt, temperature, and final output).
    ```

*   **Continued Conversation:**
    ```bash
    python -m lab chat "and add comments?" --continue
    # Purpose: Continues an ongoing conversation thread by feeding the history back into the model.


#### Verification & Testing (`lab verify` / `pytest`)

These commands are used for evaluating outputs, whether they were generated by the system or provided externally.

*   **Judging Written Text (Standalone):**
    ```bash
    python -m lab verify --response reponse.md --judge always --trace
    # Purpose: Evaluates a pre-written document (`reponse.md`) against set criteria without generating new content.
    ```

*   **RAG Verification (Retrieval Augmented Generation):**
    ```bash
    python -m lab verify --response r.md --chunks chunks.json --question "..."
    # Purpose: Performs verification using a specific question and a local knowledge base (`chunks.json`), simulating RAG mode.
    ```

*   **Core Unit Tests:**
    ```bash
    pytest
    # Purpose: Runs the core unit tests for the system logic, requiring no external model or API connection.
    ```

### Operational Profiles Comparison

| Profile | Key Settings | Description / Use Case | When to Use |
| :--- | :--- | :--- | :--- |
| **Latency** | `annotate`, `auto-judge` | Immediate response with real-time status updates. | Need instant feedback (e.g., live chat). |
| **Balanced** | `gate`, Temp: `0.7`, Rounds: `2` | The default, stable setting balancing speed and quality. | General purpose tasks; standard usage. |
| **Quality** | `gate`, Temp: `0.95`, Rounds: `3`, Secondary Judge | High-accuracy mode using multiple refinement rounds and a secondary judge model. | Mission-critical content requiring maximum reliability. |

*Note: Parameters are listed in the order: [Validation Method], Temperature, Number of Refinement Rounds.*
